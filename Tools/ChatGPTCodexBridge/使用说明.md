# ChatGPT 向当前 Codex 聊天转发指令

这是已准备好的本地 STDIO MCP 服务。没有修改应用设置，没有发送测试消息。
只能发到固定会话 `01a0799c-4ed6-75f1-98ee-5e7cae6f842f`，不能指定其他会话。
发送的是后续消息，接收端继续沿用原会话的权限和审批规则。

## 在桌面应用添加

发送方应使用桌面应用中的本地 Work，工作位置选择这台电脑。
普通云端聊天不会因处于同一应用中就自动获得本机 MCP 工具。

1. 设置 → MCP servers（MCP 服务器）→ Add server（添加服务器）。
2. 名称填 `chatgpt_codex_bridge`，类型选 `STDIO`。
3. Command（命令）填：

   `D:\UE\Project\HorrorGame\Tools\CLI-Anything\venv\Scripts\python.exe`

4. Args（参数）分为两项：

   `-u`

   `D:\UE\Project\HorrorGame\Tools\ChatGPTCodexBridge\bridge.py`

5. Working directory（工作目录）填 `D:\UE\Project\HorrorGame`。
6. 将发送工具的审批设为“每次询问”。本目录 `config_to_add.toml` 提供精确配置。
7. 保存后按应用的 Restart 重新载入服务。不要在其他任务尚未保存时自行重启应用。
8. 在新的本地 Work 聊天输入 `/mcp`，确认服务已连接。若该聊天看不到本机服务，应先核对运行位置。

配置片段只需合并一次，不能直接覆盖原来的 config.toml。

## 检查与发送

先让发送方调用 `bridge_info` 和 `prepare_instruction`。这两个工具不会发消息。
确认目标后，用户可以明确要求：

“请通过 chatgpt_codex_bridge 的 send_instruction，向当前建模会话发送：
只回复‘连接成功’，不要进行其他工作。我授权发送这条测试消息。”

发送方需生成唯一 request_id、将 human_requested 设为 true，并取得发送批准。
相同 request_id 重复调用不会再次发送。超时属于结果不确定，需先查看目标聊天，不能盲目换 ID 重试。

`queued` 只说明本地 Codex 队列命令成功，不能当成任务已经开始或完成。
要在接收会话里看到测试回复，才算验证实际链路。

## 安装范围

使用现有 Python 环境中已安装的 MCP SDK，不需要新增下载。
STDIO 不监听网络端口；转发时调用本机 Codex CLI `queue --thread ... --message ... --resume`。
首次真实发送会在本目录创建 submissions.sqlite3，只记请求编号、消息哈希和命令结果。
不会将消息正文写入去重数据库；消息仍会进入目标 Codex 聊天的正常历史。

本工具不读取完整聊天历史，也不提供任务进度接口。
如果后续 Codex 更新移除了旧的 codex.exe 路径，需要更新 bridge_config.json 的 codex_binary。

官方本地 MCP 配置：https://learn.chatgpt.com/docs/extend/mcp
